# Phase6-Step2 計画書: `ControlService.cs` のGlobal直参照解消

作成日: 2026-09-09
対象ブランチ: `For-DI-migration-work`
上位計画書: `docs-forDIMG/MadeByAgent/Phase6-Plan.md`
着手前提: Phase6-Step1（詳細監査と対象確定）の完了、および`Phase6-Step1-Global-Usage-Classification-Report.md`の承認

---

## 0. 前提の明記

本計画書は、Phase6-Plan.md §0.2記載の暫定値（`ControlService.cs`内39件）を基に、**作業方針・ガードレール・PR分割方針を先行して定義**するものである。**対象の確定件数・個別のメンバ名・移行先サービス名は、Step1の成果物（`Phase6-Step1-Global-Usage-Classification-Report.md`）の確定を待って本計画書に反映し、差分があれば改訂版を作成してから着手する。**

Step2は、Phase6の中で**最優先かつ最難関**と位置付けている。理由は以下の通り。
- `ControlService.cs`は4層モデルにおける信号変換層／入力監視層の境界に位置する中核コンポーネントである。
- 一部の参照は入力ポーリングループ（毎秒250〜1000回）から直接・間接に呼ばれるホットパスに該当し、単純な機械的置換では済まない可能性がある。
- Phase3で発見された`ControlService ⇄ Mapping`循環依存の経緯からも分かる通り、このファイルへの変更は波及範囲の見極めが難しい。

---

## 1. 目的

`ControlService.cs`内の`Global.*`直接参照（Step1確定値、暫定39件）を、既存または軽微拡張したDIサービス経由の呼び出しへ置換し、信号変換層／入力監視層境界のGlobal依存を解消する。

---

## 2. 作業方針

### 2.1 分類ごとの対応方針

Step1の分類結果（(a)単純リダイレクト／(b)中程度作業／(c)要設計）に従い、以下の順序で対応する。

1. **(a)単純リダイレクトから着手**: 既存DIサービス（`IProfileSettingsService`, `IDeviceStateService`, `IEnvironmentService`等）に既にメンバがあるものから、リスクの低い順に置換する。
2. **(b)中程度作業**: 既存サービスへの軽微拡張が必要なものは、Phase5-Step14前クリーンアップ（PR-B〜D）と同一パターン（`Global`への薄いシムとして追加）で対応する。
3. **(c)要設計**: 新規インターフェースが必要な項目があれば、着手前にユーザーへ設計案を提示し承認を得る。Step2の中で追加のサブフェーズ（Step2-1, Step2-2, ...）として細分化する。

### 2.2 ホットパス該当項目への特別対応

Step1でホットパス該当と判定された項目については、以下の追加手順を踏む。

1. 置換前に、該当箇所を含む処理の呼び出し頻度・呼び出し経路を`ControlService.On_Report`等の実装から確認する。
2. DIサービス側の実装は、内部キャッシュを持たずBackingStoreへ直接委譲する形とする（Phase5-Step10で撤廃した「起動時キャッシュ」の再発防止）。
3. 置換後、可能であれば簡易ベンチマーク（同一操作の入力→出力遅延比較、または処理時間計測ログ）で性能劣化がないことを確認する。実機での体感確認が主体となる場合は、Step9（自動テスト・実機検証）の確認項目として明示的に引き継ぐ。

### 2.3 Halt保証との整合

`InitOutputKBMHandler`関連等、出力ハンドラの初期化・再初期化に関わるメンバについては、既存のHalt機構（入力停止・再開の仕組み）との整合を崩さないことを個別に確認する。該当メンバがあれば、Step1の成果物で明示的にフラグを立てておくことをStep1側にも申し送る。

## 3. PR粒度・実施順序

1 PR = 1分類 or 1機能グループを基本とする（Phase5-Plan.md §7の原則を継承）。

| PR | 内容 |
|---|---|
| PR-1 | 分類(a)のうち非ホットパス項目（低リスク） |
| PR-2 | 分類(a)のうちホットパス該当項目（ベンチマーク比較を伴う） |
| PR-3 | 分類(b)（既存サービスへの軽微拡張＋呼び出し側置換） |
| PR-4（該当時のみ） | 分類(c)（新規インターフェース設計・実装・配線） |

各PR完了ごとに、既存自動テスト（Actions/Standalone）を実行し、回帰がないことを確認してから次のPRへ進む。

## 5. リスクと対応

| リスク | 対応 |
|---|---|
| ホットパス項目の置換により入力遅延が悪化する | §2.2の手順でベンチマーク比較を実施。悪化が確認された場合は、当該項目のみGlobal直接参照を意図的に残す例外として記録し、Phase6完了条件の「例外リスト」に追加する |
| `ControlService ⇄ Mapping`循環依存の再燃 | 置換対象が`Mapping.cs`側にも影響する場合、Step3（Mapping.cs残存参照の再点検）と連携して同時に検討する。単独Stepでの拙速な変更は避ける |
| Step1の実測件数がPhase6-Plan.mdの暫定39件から大きく乖離する | 乖離が大きい場合、本計画書を改訂してから着手する（§0参照） |
